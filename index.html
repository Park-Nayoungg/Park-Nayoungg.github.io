사례 1 · 이메일로 하던 운영을 인터니 한 곳으로, 2주 안에 출시

문제
학생과 관리자가 이메일로 과제를 주고받아 누가 제출하고 출석했는지 한눈에 보기 어려웠습니다. 기업 고객이 이걸 인터니에서 하고 싶다고 요청했습니다.
판단
기획팀과 요청을 '이번에 꼭 필요한 기능'과 '다음 단계'로 나눴습니다. "여러 담당자가 같이 관리하고 싶다"는 모호한 요구는 기관 멤버십, 초대 승인, 활동별 권한 구조로 구체화해 다시 합의했습니다. 디자인팀과는 모바일·예외 화면을 함께 조율했습니다.
결과
약 2주 만에 과제 제출(파일·링크)과 평가, 출석 체크, 엑셀 내보내기를 출시해 이메일 업무를 대체했습니다.

사례 2 · 영상 렌더링으로 생긴 서버 부하 해결

문제
기업 요청으로 브이로그 기능을 1주 만에 출시했지만, FFmpeg로 영상을 합치고 자막을 입히는 작업이 몰리면 서버 부하가 커졌습니다.
시도
렌더링을 전용 비동기 Executor로 분리하고 동시 실행 수, 대기 큐, FFmpeg 스레드 수를 제한했습니다. 문제가 생기면 내보내기 API만 임시로 막을 수 있게 설계했습니다. 큰 파일은 S3 Presigned URL로 앱에서 바로 올리게 했습니다.
결과
영상 기능을 유지하면서 렌더링으로 인한 서버 부하를 줄였습니다.

사례 3 · 데이터를 보고 불필요한 연산 99% 줄이기

문제
리더보드 랭킹 스냅샷을 10분마다 계산해 하루 144번 집계가 돌았습니다. DB를 보니 미션 제출이 없는 기간에도 스냅샷이 1,300건 넘게 쌓여 있었습니다.
시도
갱신 주기를 매일 오전 10시 1회로 바꾸고, 점수·추세 계산 결과는 테스트 코드로 검증했습니다.
결과
집계 실행을 하루 144회에서 1회로 줄이고(약 99% 감소) 불필요한 데이터가 쌓이지 않게 했습니다.

사용자 경험을 다듬은 디테일

  • 질문 문장의 조사(을/를, 이/가)를 단어에 맞게 자동 변환
  • 탈퇴한 계정으로 로그인하면 안내 화면, 학생증 인증이 거절되면 사유를 모달로 안내
  • 시작일 이전 마감일 선택 막기, 기록이 있는 날짜 밖으로 기간 변경 막기
  • 녹음 파일 용량 초과 안내, 프로필 사진 편집
  • 제출 파일을 다운로드 없이 미리보기 (권한 확인 후 5분 만료 링크 발급)
  • 리프레시 토큰 재발급이 여러 번 호출되던 문제 수정
  • 해외 사용자를 위한 시간대 처리와 한/영 번역 키 관리
  • 앱 이미지 용량 최적화, 화면 전환 애니메이션, 딥링크 처리
기술 선택과 이유 펼치기
  • React Native · 이미 만든 웹 기능을 iOS·Android에 빠르게 옮기려고 하나의 코드로 두 앱을 만드는 방식을 골랐습니다.
  • S3 Presigned URL · 큰 영상·과제 파일이 API 서버를 거치지 않게 해 서버 부담을 줄였습니다.
  • Firebase FCM · iOS·Android 푸시를 한 방식으로 보내고, 기기 언어에 맞춰 한/영 알림을 보냈습니다.
  • user_auth_providers 테이블 · 카카오만 쓰던 로그인에 구글·애플·이메일을 더하면서, 한 사용자가 여러 로그인 수단을 쓸 수 있게 분리하고 기존 사용자 정보를 옮겼습니다.
  • 30일 유예 탈퇴 · 실수로 탈퇴한 사용자가 복구할 수 있게 바로 지우지 않고, 30일 뒤 스케줄러가 데이터와 S3 파일을 정리합니다.
